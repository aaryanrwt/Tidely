# Tidely Enterprise v1.4.3 Developer Walkthrough

Welcome to the Tidely Enterprise v1.4.3 walkthrough. This document details how to use and verify the new features of the library, including cell-level diffs, compliance auditing, statistical drift analysis, and safety invariant validation.

---

## 1. Quick Start (Simple Two-Line API)

Tidely protects the public API so that complex auditing, profiling, and cleaning happen completely automatically under the hood:

```python
import tidely as td

# Clean a dirty dataset from CSV, Parquet, Pandas, Polars, or PyArrow
result = td.clean("dirty_dataset.csv")

# The result acts like a normal DataFrame, but contains rich auditing features
print(result.head())
```

---

## 2. Cell-Level Diffs (`result.diff()`)

To see exactly what cells changed, why they changed, and what they would look like in a traditional pandas-style pipeline, use `result.diff()`:

```python
diff_report = result.diff()

# diff_report behaves like a Pandas DataFrame
print(diff_report.columns)
# Output: ['Row', 'Column', 'Original Value', 'Traditional Pipeline Value', 
#          'Tidely Value', 'Rule Applied', 'Statistical Reason', 
#          'Execution Time', 'Backend Used', 'Planner Decision']

# Exporting diffs in various formats
diff_report.to_csv("reports/diff.csv")
diff_report.to_parquet("reports/diff.parquet")
diff_report.to_json("reports/diff.json")
diff_report.to_markdown("reports/diff.md")
```

---

## 3. Compliance Auditing (`result.audit()`)

For enterprise data governance, `result.audit()` returns a complete audit trail of host environment details and cryptographic fingerprints:

```python
audit_log = result.audit()

# The log captures OS, CPU, RAM, Python/Tidely versions, pre/post fingerprints, and warnings
print(audit_log.log_dict["os"])
print(audit_log.log_dict["dataset_fingerprint"]["sha256"])

# Export logs
audit_log.to_json("reports/audit_log.json")
audit_log.to_markdown("reports/audit_log.md")
audit_log.to_html("reports/audit_log.html")
```

---

## 4. Explainability Engine (`result.explain()`)

Each cleaning action is backed by measurable statistical evidence (e.g., skewness thresholds, normality tests) generated by the Decision Engine:

```python
explain_report = result.explain()

# Print statistical reasoning for a specific column
age_explanation = explain_report.get("age", {})
print(f"Role: {age_explanation.get('role')}")
print(f"Decision: {age_explanation.get('decision')}")
print(f"Normality p-value: {age_explanation.get('evidence', {}).get('normality_pvalue')}")
```

---

## 5. Statistical Drift Analysis

Verify that cleaning didn't introduce unexpected bias or statistical drift using `result.distribution_drift_report()`:

```python
drift_report = result.distribution_drift_report()

for col, metrics in drift_report.items():
    print(f"Column: {col}")
    print(f"  Kolmogorov-Smirnov p-value: {metrics['metrics']['ks_pvalue']}")
    print(f"  Wasserstein Distance: {metrics['metrics']['wasserstein_distance']}")
    print(f"  PSI (Population Stability Index): {metrics['metrics']['psi']}")
```

---

## 6. Safe & Revertible Operations

If you need to discard all cleaning actions and retrieve the original dataset state:

```python
original_df = result.undo()
```

And rest assured that Tidely's strict safety checks will abort execution with a `SafetyValidationError` if target labels, primary keys, or foreign keys are mutated.

## 7. Directory Structure

```
src/tidely/
├── __init__.py         # Public API definition
├── api.py              # Main td.clean entrypoint
├── result.py           # CleanResult, CleaningDiff, and AuditLog
└── core/
    ├── audit.py        # Safety validation, fingerprints, drift, preservation
    ├── semantic.py     # Semantic Engine for role inference (e.g. Primary Key, Target)
    ├── plan.py         # Repair planning logic
    ├── decision_engine.py # Statistical decision heuristics
    └── scorer.py       # Lighthouse trust score computations
```
